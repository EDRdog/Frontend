# EDRdog Frontend 기능 명세

지금 구현된 것 기준이다. 데이터는 전부 백엔드 `api-service` 에서 온다.

## F1. 랜딩과 로그인

| | |
|---|---|
| `/` | 서비스 소개. 스크롤로 이어지는 히어로(이벤트 → 탐지 → 대시보드), 조사·대응, 위협 지도·관계 분석, 기능 벤토, CTA, 테마 토글 |
| `/login` | 로그인과 회원가입 통합 폼(탭 전환) |
| 세션 | 토큰을 localStorage 에 두고 새로고침해도 유지한다. 값이 깨져 있으면 로그아웃 상태로 시작 |

## F2. 비로그인 데모

조회 탭은 **로그인 없이 열린다.** 토큰이 없으면 데모 데이터를 그린다. 처음 온 사람이 서비스가 무엇을 보여주는지 볼 수 있어야 해서다.

`/me/*` 와 `/tenant/*`(개인 설정)는 데모가 없다. 보여줄 "예시" 가 없는 영역이라 비로그인 시 호출하지 않는다.

## F3. 대시보드 (`/dashboard`)

가장 급한 미판단 위협 하나를 크게(세로 공격 흐름, 권고 대응, 판정 버튼), 오른쪽에 미판단 대기열과 엔드포인트 상태. 아래에 접히는 한눈에 보기(위협 탐지 추이, 위협 유형 TOP5)와 24시간 이벤트·주간 탐지 수. 미판단 위협이 없으면 "지금 처리할 위협이 없습니다" 와 추이·엔드포인트 상태를 크게 보여준다.

## F4. 조사 화면

| 경로 | 보여주는 것 |
|---|---|
| `/threats` | 상태별 보드(미판단, 확정, 오탐 열). 열마다 따로 조회하고 더 보기로 이어 붙인다. 심각도 칩 필터, 호스트·도메인·목적지IP 필터 |
| `/endpoints` | 고른 호스트 하나를 크게(상태, 위험도, 활동 시각, 프로세스 트리, 이 호스트의 위협)와 오른쪽 위험도 순 호스트 목록. 정상/주의/위험/**수집없음** 필터, 상세로 가는 링크 |
| `/endpoints/:host` | 호스트 상세. 요약, 프로세스 트리, 이 호스트의 위협·사건·최근 로그 |
| `/events` | 원시 이벤트. 고른 이벤트 하나를 크게(명령줄, 상세 필드, 원본 JSON)와 오른쪽 최신순 이벤트 흐름. 기간·호스트·유형 필터, 검색으로 연 이벤트를 먼저 띄움 |
| `/incidents` | 사건 카드(알림을 프로세스 계보로 묶은 것). 카드마다 루트 프로세스에서 이어진 탐지 체인. 기간·상태 필터, 누르면 상세 |
| `/incidents/:id` | 사건 상세. 요약, 사건 단위 트리아지, 계보, 구성 알림, 증거 사슬, 전개 타임라인 |

"수집없음" 을 "정상" 과 분리한 이유는 등록만 되고 이벤트가 없는 기기에 초록을 쓰면 검증 안 된 상태를 좋다고 말하는 셈이기 때문이다. 중립색으로 따로 둔다.

## F5. 분석 화면

| 경로 | 보여주는 것 |
|---|---|
| `/intelligence` | 관계 분석. 엔드포인트 → 목적지 egress 토폴로지 그래프. 알림 유무로 선 스타일 구분 |
| `/lookup` | IP·도메인 조회. 상관 그래프(관측/추정/실시간DNS 출처 구분) + 실시간 정·역방향 DNS |
| `/map` | 위협 지도. 외부 연결 목적지를 국가별로 집계해 세계지도에 표시 |

**관측·추정·실시간 조회를 시각적으로 구분한다.** 셋을 같게 보여주면 추측이 관측으로 읽힌다.

## F6. 대응

알림이나 사건에서 확인을 거쳐 프로세스 종료를 지시한다. `POST /api/alerts/:id/respond` 로 api-service 를 거쳐 나간다. 결과는 1초 간격 폴링으로 받고 40초가 상한이다.

격리(isolate)는 백엔드에 구현이 없어 프로세스 종료로 대신한다. 화면에 격리로 남겨 두면 격리된 줄 알고 넘어가게 되므로 표현을 걷어냈다.

## F7. 온보딩 (`/onboarding`)

에이전트 설치 안내(OS별 명령과 경로), Slack webhook 등록, 기기 상태 확인, 내 기기 등록.

설치 링크는 서버가 준 것을 그대로 쓴다. 화면에서 조립하지 않는다. 둘이 어긋나면 사용자가 붙여넣은 명령이 조용히 틀린 곳을 가리킨다.

enroll secret 은 화면에 보여주지 않는다. 키를 사람 손에 쥐여 주면 채팅방에 붙고 스크린샷에 남는다.

## F8. 공통 기능

| | |
|---|---|
| 통합 검색 | 상단바. 서버 `GET /api/search` 를 친다 |
| 자동 새로고침 | 10/30/60/300초. **기본값은 꺼짐** |
| 테마 | 다크/라이트 토글. 최초값은 OS 설정 추종 |
| 반응형 | 모바일 드로어 |

## F9. 보안 기능 관리 (admin 전용)

로그인해야 열린다(데모 없음). 사이드바 PLATFORM 묶음에 있고, viewer 에게는 숨긴다. 서버도 viewer 에게 403 을 준다.

| | |
|---|---|
| `/settings/password` | 비밀번호 변경. 규칙 목록이 입력에 따라 지킴·어김으로 바뀐다 |
| `/settings/policy` | 로그인 보안정책(연속 실패 횟수, 잠금 시간, 유휴 세션 종료) |
| `/settings/ip` | 관리 IP 허용 목록. 비어 있으면 제한 없음 |
| `/settings/accounts` | 같은 조직에 viewer 계정 만들기 |
| `/audit` | 감사기록. 기간·유형·행위자·결과 필터, 시각 정렬, 쪽 이동 |
| `/selftest` | 서버 자체시험과 무결성 검증 결과, 지금 실행 |
| `/password-change` | 기본 비밀번호로 로그인한 계정이 바꾸기 전까지 머무는 화면. 셸 없이 이것만 보인다 |

서버가 세션을 끝내면(유휴 종료, 다른 곳에서 로그인, 만료 → 401) 로그인 화면으로 보낸다. 기본 비밀번호를 안 바꾼 계정이 다른 API 를 부르면 서버가 403(`password_change_required`)을 주고, 화면은 강제 변경 화면으로 보낸다.

viewer 는 대응(프로세스 종료)과 판단(확정, 오탐) 버튼도 못 본다.

왜 화면에 서버 규칙이 적혀 있는지는 [ADR 013](../design-docs/decisions/013-kisa-security-screens-show-server-rules.md).

## 비기능 요건

| | |
|---|---|
| 번들 | Vercel Hobby 플랜 안에서 돌아야 한다. echarts 를 쓰는 화면은 지연 로드한다 |
| 아이콘 | 외부 아이콘 라이브러리와 이모지를 쓰지 않는다. 인라인 SVG 만 |
| 색 | 심각도 전용. 이벤트 유형 같은 다른 축에 색을 주지 않는다 |
| 지어내지 않기 | 로그인 상태의 빈 화면을 예시 데이터로 채우지 않는다 |
| 서버 규칙 | 서버가 정하는 판정 규칙을 화면 문구에 옮겨 적지 않는다. 단 F9 의 보안 기능 화면은 안내용으로 적는다(ADR 013) |
| 필터·검색 | 화면에서 거르지 않고 서버에 넘긴다 |
