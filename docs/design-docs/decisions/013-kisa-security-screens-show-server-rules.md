# 013. KISA 보안 기능 화면은 서버 규칙을 화면에 안내용으로 적는다 (011 의 예외)

- 날짜: 2026-11-11
- 상태: 채택

## 배경
KISA 보안 기능(비밀번호 규칙, 보안정책, 관리 IP, 감사기록, 자체점검)을 관리하는 화면을 만든다. 백엔드(`api-service`)가 규칙을 정하고 서버가 최종 판정한다.

[011](011-no-server-rules-in-ui-text.md) 은 서버가 정하는 규칙을 화면 문구에 옮겨 적지 않는다고 했다. 그런데 이 화면들은 규칙을 보여주는 것이 기능이다. 사용자가 비밀번호를 쓰기 전에 어떤 규칙이 있는지 알아야 하고, 보안정책 입력칸은 허용 범위를 알려줘야 한다. 시안(`docs/design-docs/previews/kisa-security.html`)도 규칙 목록과 범위를 화면에 두고, 사용자가 시안대로 구현하라고 정했다.

## 결정
이 화면들에 한해 서버 규칙을 화면에 적는다. 단 **안내용**이다. 화면의 규칙은 입력을 미리 알려주고 저장 버튼을 막는 데에만 쓰고, 최종 판정은 서버가 한다. 서버가 400 으로 돌려주는 이유는 화면이 가공하지 않고 그대로 보여준다.

화면에 옮겨 적은 규칙은 다음과 같다. 백엔드가 바꾸면 여기도 같이 고친다.

| 규칙 | 화면 위치 | 백엔드 출처 |
|---|---|---|
| 비밀번호 9자 이상, 대문자·소문자·숫자·특수문자, 아이디와 다름, 같은 문자 3연속 금지, 키보드 순서 3자 금지 | `src/lib/password.ts` | `AuthValidation.passwordError` |
| 직전 비밀번호 재사용 금지 | 화면이 판정하지 않는다. "저장할 때 확인" 으로만 알리고 서버 400 을 보여준다 | `AuthService.changePassword` |
| 연속 실패 1~5회, 잠금 5~1440분, 유휴 종료 1~60분 | `src/pages/settings/PolicyTab.tsx` | `SecurityPolicyService` |
| 허용 IP 는 단일 IPv4·IPv6, 처음 등록은 내 IP | `src/pages/settings/IpTab.tsx` | `AdminIpService` |

## 근거
- 011 이 막으려던 것은 "규칙이 바뀌었는데 화면만 옛 설명을 사실처럼 보여주는 것" 이다. 이 화면들은 규칙 자체가 보여줄 내용이라 문구를 빼면 기능이 사라진다.
- 그래서 문구를 뺄 수는 없고, 틀렸을 때의 피해를 줄인다. 화면이 틀려도 서버가 거절하므로 보안이 약해지지는 않는다. 화면이 더 엄격하면 쓸 수 있는 값이 막힐 수 있고, 더 느슨하면 저장할 때 서버가 거절한다. 어느 쪽이든 서버의 400 문구가 그대로 보인다.
- 버린 대안: 규칙을 서버에서 받아 그리기. 백엔드에 규칙을 내려주는 API 가 없고, 이 규칙은 KISA 평가 기준표를 옮긴 것이라 자주 바뀌지 않는다. 필요해지면 그때 만든다.
- 시안의 보안정책 잠금 시간은 "5분 이상" 이라고만 적었지만 서버는 5~1440분만 받는다. 화면 범위는 서버 값(1440)을 따랐다.

## 결과/영향
- 백엔드가 비밀번호 규칙이나 정책 범위를 바꾸면 위 표의 화면도 같이 고쳐야 한다. 둘이 어긋나는 것을 잡아낼 장치는 없다(타입체크로 안 잡힌다. `docs/exec-plans/tech-debt.md`).
- 이 예외는 위 화면들에만 적용한다. 호스트 상태, 위험도 같은 판정 규칙을 화면 문구로 옮겨 적는 것은 여전히 011 대로 금지다.
- 이 작업으로 `RequireAuth` 가 살아났다. 데모가 없는 화면(`/settings/*`, `/audit`, `/selftest`, `/password-change`)만 감싼다. 조회 탭은 [002](002-demo-without-login.md) 대로 로그인 없이 열린다.
