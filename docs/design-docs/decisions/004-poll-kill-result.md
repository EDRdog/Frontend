# 004. 조치 결과를 폴링으로 받는다

- 날짜: 2026-09-18
- 상태: 채택

## 배경
백엔드가 kill 을 비동기로 바꿨다. `POST` 는 202 와 명령 id 만 주고 결과는 따로 조회해야 한다. 에이전트가 하트비트를 보낼 때까지 결과가 없다.

## 결정
명령 id 로 결과를 폴링한다.

```js
/** 결과 조회 간격. 서버가 30초에 TIMEOUT 을 주므로 40초가 지나면 스스로도 멈춘다. */
const POLL_MS = 1000
const POLL_LIMIT_MS = 40_000
/** 502 같은 일시 오류를 연달아 몇 번까지 참을지. */
const POLL_RETRIES = 3
```

멈추는 조건이 셋이다.

- 화면을 떠나면 멈춘다
- 4xx(남의 알림, 모르는 명령)는 다시 물어도 같으니 바로 멈춘다
- 서버 TIMEOUT 도 못 받고 상한을 넘기면 시간 초과로 본다

## 근거
상한 40초는 서버의 30초 TIMEOUT 보다 길게 잡은 값이다. 서버가 판단한 TIMEOUT 을 받는 것이 정상 경로이고, 그것조차 못 받는 경우에만 클라이언트가 스스로 끊는다.

4xx 를 재시도하지 않는 이유는 같은 답이 오기 때문이다. 재시도는 일시 오류(502 등)에만 쓴다.

## 결과/영향
- 결과가 푸시되지 않는다. 화면을 떠나면 그 요청의 결과를 못 본다.
- 이전에는 Fleet 이 kill 을 대신 실행했고 "폴링 방식이라 반영까지 수십 초" 라는 안내가 온보딩에 남아 있었다. 에이전트가 직접 죽이게 되면서 그 문구를 지웠다.
- 조치가 실제로 됐는데도 화면에 작은 글씨 한 줄뿐이라 알아보기 어려웠던 것을 따로 고쳤다.
