# 007. 목록을 서버 페이지네이션으로 받는다

- 날짜: 2026-08-01
- 상태: 채택

## 배경
목록을 한 번에 받아 화면에서 다뤘다. 호스트가 7대일 때는 티가 안 났다.

## 결정
쪽 단위로 받는다. 페이지 정보는 응답 헤더로 읽는다.

| 헤더 | 쓰임 |
|---|---|
| `X-Has-More` | 다음 쪽 유무 |
| `X-Total-Count` | `withTotal` 을 준 첫 쪽에만 온다 |
| `X-Time-From`, `X-Time-To` | 서버가 실제로 적용한 구간 |

목록 훅은 `usePagedList` 하나로 모았다.

## 근거
**`X-Total-Count` 로 다음 쪽을 판단하지 않는 이유**:
> total 은 withTotal 을 준 첫 쪽에만 오므로 그걸로 판단하면 2쪽부터 틀린다.

**구간을 고정해 보내는 이유**:
> from/to 는 서버가 실제로 적용한 구간이다. 조회가 최신순이라 그사이 새 데이터가 쌓이면 offset 이 밀려 행이 겹치거나 건너뛰어진다.

**offset 상한이 있는 이유**: ClickHouse 의 OFFSET 은 건너뛸 행을 실제로 읽는다. 깊이 파는 수단이 아니다. 넘기면 서버가 400 을 준다.

**훅을 공용으로 뺀 이유**:
> 목록 세 곳이 같은 100줄짜리 훅을 그대로 복사해 갖고 있었다. 미묘한 비동기 로직이 세 벌이면 아래 같은 결함도 세 번 고쳐야 한다.

## 결과/영향
- CORS 에서 이 헤더들이 노출돼야 한다. 없으면 페이지 정보가 null 로 떨어진다.
- 깊은 페이지로 가는 대신 `from`/`to` 로 범위를 좁히게 안내한다.
