# 015. 콘솔과 랜딩 리디자인 방향을 정한다 (미드나잇·클라우드, 소프트 UI, 페이지별 배치)

- 날짜: 2026-11-11
- 상태: 채택 (2026-11-11, 시안 선택 결과 참고)

## 배경
현재 화면이 색감이 애매하고 딱딱하며 AI가 만든 티가 난다는 피드백. 진단 결과:
- 강조색 `#4a76e8` 이 채도가 어중간하고, 사이드바 메뉴 글자 전체가 파랑이라 강조가 강조로 읽히지 않는다.
- 심각도 높음이 노랑이라 주의(노랑)와 겹친다.
- KPI 카드 2개가 큰 여백만 차지하고, TOP 5와 이벤트 막대가 의미 없이 같은 색이다.
- 추이 차트가 매끈한 곡선이라 건수(정수) 데이터와 맞지 않는다.

참고: Techeer-Bootcamp-2026-Summer-Team-C/team-C(OWLBY) 프론트. 무채색 바탕, 로열 블루 하나, 선택 메뉴만 채움, mono 라벨, Evidence chain, 신호 스트립.

## 결정
- 색: 무채색 바탕 + `--accent #2b63f0` 하나 + 심각도 4색(심각 빨강, 높음 주황, 보통 노랑, 정상 초록). 상세는 `DESIGN.md`.
- 구조는 그대로 두고(메뉴, 문구, 데이터) 위계만 바꾼다: 신호 스트립, KPI 4칸, 번호 붙은 증거 체인, 심각도 띠가 있는 표, 막대 추이 차트.
- 글꼴은 기존 Pretendard + JetBrains Mono 를 유지한다.
- 랜딩은 같은 토큰 위에서 토스식 문장 등장 + 리니어식 다크 톤, GSAP ScrollTrigger 로 연출한다.

## 근거
- 참고 레포의 구조를 통째로 가져오지 않은 이유: 메뉴와 화면 구성은 이미 비슷하고, 문제는 색과 위계였다. 바꾸는 범위를 토큰과 컴포넌트 모양으로 줄인다.
- 버린 대안: Inter 로 글꼴 교체(한글은 Pretendard 가 그대로 쓰여 효과가 작음), 좌측 사이드바 제거(메뉴가 9개라 상단바에 다 안 들어감), 라이트 기본(관제 화면은 다크가 기본이라는 기존 방향 유지).
- 시안: `docs/design-docs/previews/dashboard.html`, `docs/design-docs/previews/landing.html`

## 시안 선택 결과 (2026-11-11)
한 HTML 에서 색 7가지, 구성 3가지, UI 스타일 3가지를 섞어 보며 사용자가 골랐다.
- 다크: 미드나잇. 무채색 다크(`#09090b`)보다 푸른 기가 있어 덜 딱딱하다.
- 라이트: 클라우드. 애플(`#f5f5f7`), 퓨어(순백), 스톤(회백), 페이퍼(따뜻한 흰색)를 버렸다. 미드나잇과 같은 푸른 기라 테마를 바꿔도 같은 제품처럼 보인다.
- 화면 구성: 사이드바 유지. 아이콘 레일, 상단 메뉴를 버렸다.
- UI 스타일: 소프트(둥근 모서리, 옅은 그림자). 라인(1px 테두리), 플랫(면 색 단계)을 버렸다. 처음 정한 곡률 6px 이하, 그림자 금지 규칙은 이 선택으로 바꿨다(DESIGN.md 4장).
- 사이드바 스타일: 기본(영문 그룹 라벨, 선택 항목 파랑 채움) 유지. 한글 그룹의 정리형, 구분선만 두는 미니멀을 버렸다.
- 대시보드 배치: 포커스(가장 위험한 사건 하나를 크게, 나머지는 오른쪽 대기열). 브리핑을 추천했으나 사용자가 포커스를 골랐다. 사이드바 각 페이지도 목록형, 포커스형, 페이지별 안 세 배치를 시안으로 비교 중.

## 페이지별 배치 결정 (2026-11-11)
각 페이지를 목록형(A), 포커스형(B), 페이지별 안(C) 세 가지로 비교해 사용자가 골랐다.

| 페이지 | 선택 | 모습 |
|---|---|---|
| 대시보드 | 포커스 | 가장 위험한 사건 하나를 크게, 오른쪽 대기열, 아래 접히는 한눈에 보기 |
| 위협 | C 상태별 보드 | 미판단, 확정, 오탐 칸으로 나눈 보드 |
| 사건 | C 체인 카드 | 사건마다 프로세스 흐름을 그린 카드 |
| 엔드포인트 | B 포커스형 | 선택한 호스트 상세(위험도, 프로세스 트리, 위협)와 오른쪽 위험도 순 목록 |
| 수집 로그 | B 포커스형 | 이벤트 하나를 크게, 오른쪽 이벤트 흐름 |
| 위협 지도 | B 포커스형 | 점 지도와 서울에서 나가는 연결선, 오른쪽 국가 순위 |
| 관계 분석 | C 그래프 중심 | 화면 전체를 쓰는 호스트와 목적지 연결 그림 |
| IP·도메인 조회 | C 검색 중심 | 큰 검색창 아래 연관 그래프 |
| 수집 알림 연동 | B 포커스형 | 현재 단계를 크게, 오른쪽 4단계 목록 |

- 이유: 같은 크기 박스를 바둑판처럼 까는 계기판 모습을 피하고, 페이지마다 주인공 하나를 둔다.
- 버린 것: 각 페이지의 나머지 두 배치. 시안 파일에는 비교용으로 남겨 둔다.
