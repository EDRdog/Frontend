- 이슈: #104, 브랜치: `feat/#104-console-redesign`

## 단계
1. 토큰과 공통 틀
   - `src/index.css` 다크를 미드나잇, 라이트를 클라우드 값으로 바꾸고 소프트 모양 토큰(곡률, 카드 그림자)을 넣는다
   - `Topbar` 테마 버튼을 해·달 아이콘 하나로, 로고에 흰 원 테두리
   - 배지, 카드, 버튼 같은 공통 UI 를 소프트 규칙에 맞춘다
2. 대시보드 포커스 배치
   - 가장 위험한 미판단 위협 하나를 크게(세로 공격 흐름, 권고, 판정 버튼), 오른쪽 대기열(누르면 바뀜), 엔드포인트 요약
   - 위협이 없을 때 화면, 접히는 한눈에 보기(7일 추이, 유형 TOP 5)
3. 페이지 배치
   - 위협: 상태별 보드 / 사건: 체인 카드 / 관계 분석: 그래프 중심 / IP·도메인 조회: 검색 중심
   - 엔드포인트, 수집 로그, 위협 지도, 수집 알림 연동: 포커스형(선택 항목 크게 + 오른쪽 목록)
4. 확인: `scripts/check.sh`, 두 테마에서 화면 확인, 기존 기능(판정, 조치, 필터, 페이지 넘김) 동작 확인

## 지킬 것
- 데이터 흐름(api, hooks, store)은 바꾸지 않는다. 화면 배치와 스타일만 바꾼다
- 새 의존성을 넣지 않는다
- 한 번에 한 단계씩 끝내고 `scripts/check.sh` 로 확인한다

## 1단계 메모
- 기존 토큰 이름은 그대로 두고 역할만 맞췄다: `--surface`=패널(카드), `--panel`=hover, `--panel-2`=raised(권고 박스·입력), `--line`=line-strong, `--line-2`=line, `--accent-strong`=accent-hi. 새로 넣은 것은 `--shell`(사이드바), `--accent-ink`(링크), `--med`(보통), `--wash`, `--card-line`, `--shadow-card`, `rounded-pill`.
- 곡률은 기존 스케일 값을 바꿨다(xs 3px, sm 9px, md 14px). 페이지 안의 버튼·입력·카드도 함께 둥글어진다.
- 심각도 보통(MEDIUM)은 회색에서 `--med`(노랑)로 바꿨다(`lib/format.ts`). 오탐·미등록은 회색 그대로.
- 남은 일(2·3단계): 페이지 안에서 `--high` 를 주의 뜻으로 쓰는 곳(엔드포인트 주의, 예시 데이터 배지, 연동 경고)은 `--med` 로 옮긴다. 페이지가 직접 그린 카드(대시보드 KPI 등)는 아직 테두리 카드다.

## 2단계 메모
- 대시보드를 포커스 배치로 바꿨다(`src/pages/Dashboard.tsx` 한 파일). 왼쪽은 위협 하나, 오른쪽은 대기열과 엔드포인트 상태, 아래는 접히는 한눈에 보기와 수집 수치 한 줄이다.
- 포커스 위협 고르는 법: 미판단 알림(`status=open`)을 심각도(심각 > 높음 > 보통) 다음 최신순으로 정렬해 맨 위. 대기열에서 누르면 그 위협으로 바뀌고, 판정돼 목록에서 빠지면 다시 맨 위로 돌아간다.
- 세로 공격 흐름은 기존과 같은 `api.lineage(id)` 를 `toAttackSteps` 로 편 것이다. 시안의 단계별 설명 줄(예: 매크로가 실행됐습니다)은 데이터에 없어 넣지 않았다. 계보가 비면 단계를 지어내지 않고 "재구성할 이벤트가 없습니다" 를 띄운다.
- 포커스 카드에 `key={alert.id}` 를 준다. 안 주면 위협 확정의 확인 단계(정말 확정하시겠습니까?)가 다른 위협으로 넘어가 엉뚱한 알림을 확정할 수 있다.
- 2열은 xl(1280) 부터다. 시안은 1100 이었지만 1100 에서는 사이드바(224px)가 빠져 왼쪽 카드가 460px 남짓이고, 판정 버튼 줄(`TriageActions`)이 카드 밖으로 밀려났다.
- 한눈에 보기는 열 때만 그린다. `<details>` 안의 자식은 닫혀 있어도 마운트되므로 그냥 두면 첫 화면에서 echarts 청크를 받는다.
- 엔드포인트 주의 색을 `--high` 에서 `--med` 로 옮기고 도넛을 가로 분할 막대로 바꿨다. 테두리 KPI 타일, 최근 탐지 표, 이벤트 유형별 건수 카드는 시안에 없어 뺐다(24시간 이벤트 총수는 아래 수치 줄에 남김).
- 넣지 않은 것: 마지막 수집 시각, 탐지 규칙 적중, 온라인 엔드포인트, 외부 목적지 수. 지금 대시보드가 받는 데이터에 없다. 지어내지 않는다(decision 010).
- 빈 화면은 데모에서 미판단 5건을 모두 판정하면 볼 수 있다(코드 수정 없이 확인).
- 남은 일(3단계): 상단바 예시 데이터 배지와 다른 페이지의 `--high` 주의 색, `lib/format.ts` 의 `hostStatusColor` 주의 색.

## 3A 메모 (위협, 사건, 엔드포인트, 수집 로그)
- 공통 조각을 대시보드에서 뽑아 같이 쓴다: `AttackFlow`(세로 공격 흐름), `FocusList`(포커스 배치 오른쪽 목록, 대시보드 대기열이 원본), `Tag`(MITRE·OS 태그), `Card.tsx` 의 `panelHead`. 대시보드 모습은 그대로다.
- 포커스형 2열은 대시보드와 같이 xl(1280) 부터. 1280 미만에서 오른쪽 목록을 누르면 상세가 화면 밖 위에 있어 바뀐 게 안 보이므로 상세 머리로 올려 준다(`scrollIntoView`, 상단바 높이만큼 `scroll-mt`).
- 위협(C 상태별 보드): 미판단(가장 넓음), 확정, 오탐 세 열. 열마다 `api.alertPage` 를 status 하나로 따로 부르고 열마다 더 보기가 있다. 한 목록을 받아 화면에서 나누면 열 건수가 받은 만큼으로 줄고 더 보기가 엉뚱한 열을 채워서 버렸다. 그래서 첫 화면 요청이 1개에서 3개가 됐다(같은 엔드포인트, 새 API 없음). 열 건수는 서버가 센 `X-Total-Count` 다. 열은 640px 에서 안쪽 스크롤, 1280 미만에서는 위아래로 쌓는다.
  - 옮긴 기능: 확정·오탐 칩은 열이 대신한다. 남은 칩은 심각도(전체·심각·높음·보통)이고 이제 상태와 함께 걸린다. 표의 MITRE·호스트·목적지·근거 수·탐지 시각은 카드 안으로. 목적지가 없으면 줄을 두지 않는다(예전 표는 `-`).
  - 이 화면에는 원래 판정 버튼이 없었다. 판정은 대시보드·사건 상세에서 하고, 하면 보드가 다시 받아 카드가 다른 열로 옮겨 간다(확인함).
- 사건(C 체인 카드): 사건마다 카드 한 장, 누르면 상세. 체인은 `루트 프로세스 → 탐지(최대 3개, 외 N건)` 다. 목록 응답은 `lineage` 가 null 이라(상세에서만 온다) 시안처럼 전체 계보를 그리려면 카드마다 `api.incident(id)` 를 불러야 한다. 50건이면 50번이라 하지 않았다. 루트 프로세스가 비면 "이 사건을 이을 관측이 없어 계보를 그리지 못했습니다. 루트 프로세스 확인 불가." 를 띄운다(지어내지 않는다). 전체 계보는 상세에 있다.
  - 표가 카드로 바뀌며 행 버튼(navigate)은 카드 링크(`Link`)가 됐다. 새 탭으로 열기가 된다.
- 엔드포인트(B 포커스형): 왼쪽 고른 호스트(상태, OS, 위험도 큰 숫자와 막대, 열린 위협, 마지막 활동, 에이전트 연결, 프로세스 트리, 이 호스트의 위협 최근 50건), 오른쪽 위험도 순 목록(같으면 위협 수, 이름순). 프로세스 트리와 위협은 상세 화면과 같은 `api.processTree`, `api.alerts({host})` 를 고른 호스트 하나에만 부른다. `상세 보기` 로 `/endpoints/:host` 에, `위협 보드에서 보기` 로 `/threats?host=` 에 간다. 프로세스 트리는 `toAttackSteps` 가 5단계로 자르고, 위협 목록은 360px 안쪽 스크롤이다.
- 수집 로그(B 포커스형): 왼쪽 고른 이벤트(유형·시각, 제목, 호스트·부모, 명령줄, 필드, 접힌 원본 detail, 이 호스트만 보기), 오른쪽 최신순 이벤트 흐름(640px 안쪽 스크롤, 아래 더 보기). 선택은 이벤트 `id` 로 짚어 새로고침으로 줄이 밀려도 같은 이벤트를 가리킨다.
  - 옮긴 기능: 행 펼침은 왼쪽 상세가 대신한다. 상단바 검색으로 연 이벤트(`?id&host&ts`)는 별도 카드가 아니라 왼쪽 상세 자리에 "검색으로 연 이벤트" 와 닫기로 뜬다. 흐름에서 다른 이벤트를 고르면 핀을 닫고 호스트 조건은 남긴다.
  - 큰 제목에 모르는 유형의 요약(원본 JSON)을 세우지 않는다(failure 007). 파일 이벤트의 64자 해시는 제목에서 앞 16자만, 전체는 필드에 있다.
  - 호스트 입력칸은 값이 그대로면 blur 해도 다시 조회하지 않는다. 그냥 두면 입력칸을 눌렀다 나오기만 해도 고른 이벤트가 맨 위로 돌아갔다.
  - 목록 표의 적재 시각·프로세스 줄은 흐름에서 빠지고 왼쪽 필드에 있다.
- 주의 색: `lib/format.ts` 의 `hostStatusColor` 주의와 상단바 예시 데이터 배지를 `--high` 에서 `--med` 로 옮겼다.
- 뺀 기능 없음. 시안에만 있고 데이터가 없는 것(사건 카드의 판정 버튼, 이벤트의 "이 사건 보기", 위협 카드의 근거 문장)은 넣지 않았다.
- 남은 일: 사건 카드에 전체 계보가 필요하면 화면에 들어온 카드만 상세를 부르는 방식(IntersectionObserver)을 검토한다. 상태 배지의 미판단 색은 아직 `crit` 이다(DESIGN.md 는 정보색 `--low` 지만 토큰이 없다).

## 3B 메모 (위협 지도, 관계 분석, IP·도메인 조회, 수집 알림 연동)
- 별도 워크트리에서 3A 와 병렬로 만들고 페이지 파일 4개만 가져왔다.
- 위협 지도(포커스형): 큰 지도 + 오른쪽 국가 순위. 지도 높이는 폭 기준 16:10(최대 640px). 지도 색은 echarts 가 CSS 변수를 못 읽어 `getComputedStyle` 로 토큰을 읽어 넘긴다. 중간 비중 점은 `--med`.
- 관계 분석(그래프 중심): 조건 줄, 걸린 필터, 일부 표시 안내 아래 전체 폭 그래프, 범례는 그래프 아래. 관계 수는 FilterChips.
- IP·도메인 조회(검색 중심): 큰 검색창, 목적지 칩, 결과 카드(그래프), 아래 추정 근거와 실시간 DNS.
- 수집 알림 연동(포커스형): 지금 단계 하나를 크게, 오른쪽 4단계 목록. 네 단계를 모두 그려 두고 `hidden` 으로 숨겨 입력값이 지워지지 않게 했다. "아래 3번" 같은 위치 표현을 뺐다(실패 기록 010).
- 링크 기본색 규칙 `a { color }` 를 `@layer base` 로 옮겼다. 레이어 밖에 있으면 `text-*` 유틸리티를 이겨서 링크 칩 색을 바꿀 수 없었다.
